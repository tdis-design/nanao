## 二、系統怎麼運作

| 部分 | 放在哪裡 | 誰會動它 |
|---|---|---|
| 內容（節點、連線、說明文字） | 雲端硬碟 For Website 裡的 `graphdata` | 研究人員、文字工作者 |
| 資料檔 `data/graph.json` | GitHub 專案 | 試算表按「推送」時自動寫入，人不要手改 |
| 網站畫面與功能 | GitHub 專案的 `src/` | 工程師 |

資料流向：

```
graphdata 試算表　→　選單「圖譜工具」→「推送 graph.json 到網站」
　→　GitHub 的 data/graph.json 更新　→　GitHub 自動重新建置網站（約 3～5 分鐘）　→　網站顯示新內容
```

名詞說明：

- **GitHub**：存放網站檔案的線上服務，每次修改都會留下紀錄，可以查到誰在什麼時候改了什麼。
- **GitHub Pages**：GitHub 提供的免費網站空間，本網站就放在這裡。
- **Apps Script**：附在 Google 試算表裡的小程式，負責檢查資料並送到 GitHub。程式碼備份在 `apps_script/Graph.gs`。
- **Token（權杖）**：讓 Apps Script 有權限寫入 GitHub 的一串密碼。

## 三、怎麼使用（日常更新）

### 3.1 雲端硬碟裡有什麼

```
國科會-原鄉新生四重奏…/
├─ For Website/                                 網站用的資料夾，日常只動這裡
│   ├─ graphdata                                 網站資料試算表
│   └─ 網址.txt                                  網站與 GitHub 網址
├─ 南澳知識圖譜                                  舊版（各人分頁＋ALL）
└─ 南澳知識圖譜(網頁上架用)                      舊版上架用，記憶地圖同步仍寫在這份
```

網站只讀 `graphdata`。兩份舊版在 graphdata 實測通過後會改名為 `_archive_南澳知識圖譜`、`_archive_南澳知識圖譜(網頁上架用)`；名稱開頭是 `_archive_` 的檔案是舊資料，**不要再修改**。

### 3.2 graphdata 的分頁

沿用南澳原本的習慣：所有節點放 `nodes_ALL`、所有連線放 `link_ALL`。也可以照以前的方式，每人或每個主題開自己的分頁。

| 分頁 | 用途 |
|---|---|
| `nodes_ALL` | 所有節點 |
| `link_ALL` | 所有連線 |
| `nodes_某某`、`node_某某` | （選用）個人或主題的節點分頁，例如 `nodes_竺庭`。名稱開頭對了，程式就會一起讀 |
| `link_某某` | （選用）個人或主題的連線分頁 |
| `nodes_color` | 節點分類與顏色。C、D 欄的備註（例如「ＸＸ族ＸＸ群」）程式不讀，可以照常寫 |
| `links_color` | 連線分類與顏色。D～F 欄的對應說明（例如「人－空間」）程式不讀 |
| `missing_node` | 程式自動產生：連線用到、但還沒有節點分頁建立的名稱 |
| `檢查報告` | 程式自動產生：年份、經緯度、分類顏色等提醒 |
| 其他分頁 | 程式不讀，可以自由使用 |

想暫時不讓某個分頁上網站：分頁名稱前面加 `_`，例如 `_nodes_草稿`。

欄位順序（程式依「欄的位置」讀資料，不看標題文字，所以**欄的順序不能換**）：

| 分頁 | A | B | C | D | E | F | G | H | I |
|---|---|---|---|---|---|---|---|---|---|
| nodes_ | id（名稱） | node_Group（分類） | info（說明） | start_year | end_year | Lon（經度 121.x） | Lat（緯度 24.x） | Image | 相關連結 |
| link_ | Node_A（起點） | Node_B（終點） | label（關係分類） | info（說明） | Date（年份） | | | | |

J 欄以後（例如「孤立節點」「待刪除」等註記）程式不讀，可以照常使用。

### 3.3 修改或新增資料

1. 在 `nodes_ALL` 或 `link_ALL` 編輯。新的人物、地點要先在 `nodes_ALL` 加一列，再到 `link_ALL` 連線。
2. 選單「圖譜工具」→「檢查資料（不推送）」。
3. 依顏色修正：

   | 顏色 | 意思 | 怎麼改 |
   |---|---|---|
   | 淺紅（節點 B 欄） | 同一個名稱在兩列填了不同分類 | 統一成同一個分類 |
   | 淺黃（連線 A、B 欄） | 這個名稱還沒有在節點分頁建立 | 到 `missing_node` 看清單，補進 `nodes_ALL` |
   | 淺橘 | 其他提醒，詳細說明在 `檢查報告` 分頁 | 依說明修改；不改也能推送 |

4. 選單「圖譜工具」→「推送 graph.json 到網站」。
5. 等 5 分鐘，到網站按 Ctrl + Shift + R 重新整理。想確認資料有沒有送到，看：
   https://github.com/tdis-design/nanao/commits/main/data/graph.json

### 3.4 填寫原則

- 同一個人、地點、組織只能有一種寫法。全形半形括號、空格、同音異字都會被當成不同節點，例如「尤幹 (Yukan)」和「尤幹（Yukan）」是兩個節點。
- 名稱一旦用了就不要隨便改；改了之後，連線那邊也要一起改。
- 新的分類請在 `nodes_color` / `links_color` 加一列並填色碼（如 `#E63946`），檢查時才不會被標橘。網站本身用固定的 8 大類上色（人物、組織、地景與聚落、事件、物質文化、文獻、計畫與行動、其他）；**全新的分類名稱要請工程師在 `src/state/normalizeGraph.js` 加上對應，否則網站會歸到「其他」**。關係分類裡的空格不影響，「活動/行動 參與」和「活動/行動參與」會被當成同一類。
- 年份只填數字（例如 `1957`）。不知道就留空；「現在」可以填在結束年份。其他文字會出現在檢查報告。
- 經緯度：F 欄是經度（121 開頭），G 欄是緯度（24 開頭）。填反時程式會自動對調並提醒。
- 同一條連線重複填了，網站上只會出現一次。

## 四、常見問題

| 狀況 | 原因 | 處理 |
|---|---|---|
| 推送成功但網站沒變 | 網站還在重新建置 | 再等 5 分鐘，按 Ctrl + Shift + R |
| 等了 15 分鐘還是舊的 | 自動建置失敗 | 到 https://github.com/tdis-design/nanao/actions 看最上面一筆是不是紅色叉叉，截圖給工程師 |
| 「找不到 GITHUB_TOKEN」 | Token 沒設定 | 請管理者依 `apps_script/TOKEN_設定說明.md` 設定 |
| HTTP 401 / 403 / 404 | Token 過期、權限不足或沒選到 nanao | 請管理者重新產生 Token |
| HTTP 409 | 剛好有別人同時推送 | 再按一次推送 |
| 某個節點在網站上沒有連線 | 連線兩端的名稱和節點名稱不完全一樣 | 檢查括號、空格、異體字 |
| 選單「圖譜工具」不見了 | 試算表沒有重新載入 | 按 F5 重新整理試算表 |

## 八、技術附錄（給工程師）

- 前端：React 19、D3（Canvas 力導向圖）、Tailwind CSS 4、Vite 7。
- 網站讀取同一網址下的 `./data/graph.json`，所以 `vite.config.js` 的 `base` 設為 `./`，換專案名稱不必改程式。
- 每次推送到 `main`，`.github/workflows/deploy.yml` 會建置 `dist/` 並發布到 GitHub Pages。
- 本機開發：`npm ci`、`npm run dev`。
- `src/state/normalizeGraph.js` 把 `graph.json` 轉成網站內部格式：node 的 `group` 經 `NODE_GROUP_TO_META` 對到 8 大類（網站顏色由大類決定，不用試算表的色碼）；濾掉 group 為「自動增加」的缺漏節點，以及連到它們的連線；`group` 對應到 meta_relation。
- `apps_script/Graph.gs` 輸出格式：
  - node：`{ id, group, info, start_year, end_year, lon, lat, col, sourceSheet, sourceRow, image?, url? }`
  - link：`{ source, target, group, label, info, year, color }`
  - 頂層：`{ nodes, links, legend }`
- Graph.gs 的離線測試在 `apps_script/test/test_graph.mjs`（在 repo 根目錄執行 `node apps_script/test/test_graph.mjs`）：用模擬的 Apps Script 環境測分頁判斷、缺漏與衝突標記、年份與經緯度處理、去重、推送成功／跳過／錯誤，並把輸出交給 normalizeGraph。2026-11-25 跑過 23/23 通過，輸出也實際建置成網站開啟確認。還沒在真正的試算表裡執行過，第五節的「第一次檢查與推送」就是最後一關。
- 離線資料：`npm run data` 會從 `data/source.xlsx` 產生 `data/data.json`（需 Python 3 與 openpyxl；source.xlsx 不在 GitHub 上）。
- `_git_recovery/` 是早期修復 git 用的備份，已列在 `.gitignore`，不會上傳。
- 規劃文件：`南澳知識圖譜_詳細規劃_v2.md`（資料欄位、視覺設計、分期計畫）。
