1這是什麼

南澳知識圖譜是一個網站，把宜蘭南澳 Klesan 群（泰雅族南澳群）相關的人物、部落、地點、組織、活動、物件與健康議題畫成一張關係圖。圖上每個圓點叫「節點」，每條線叫「連線」，代表兩個節點之間的關係。點一下圓點，會出現說明文字。

網站上的文字都來自雲端硬碟裡的 graphdata 試算表。改內容只要改試算表，不用碰程式，也不用找工程師。

① 編輯在 nodes_ALL / link_ALL 填資料
→
② 檢查圖譜工具 →
檢查資料（不推送）
→
③ 修正處理紅色、黃色、橘色格子
→
④ 推送圖譜工具 →
推送 graph.json 到網站
→
⑤ 等 5 分鐘網站自動重新產生
名詞小辭典
  • 節點：網站上的一個圓點，代表一個人、部落、地點、組織、活動或物件。
  • 連線：兩個節點之間的線，代表它們有關係（例如「人地關係」「活動/行動參與」）。
  • id：節點的名字，也是它的身分證。連線靠它找到這個節點。
  • 推送：按選單按鈕，把試算表的內容送到網站的資料庫（GitHub）。
  • GitHub：存放網站程式與資料的線上服務，每次修改都會留下紀錄。收到推送後會自動重新產生網站。
  • Apps Script：附在試算表裡的小程式，提供「圖譜工具」選單。
  • Token（權杖）：讓 Apps Script 能寫入 GitHub 的一串密碼，由管理者設定，一般使用者不用碰。

4打開 graphdata 與選單

  1. 從第 3 節的連結（或雲端硬碟 For Website 資料夾）打開 graphdata。
  2. 等畫面載入完成（約 3～5 秒），上方選單列最右邊會出現 圖譜工具。
  3. 點開會看到兩個選項：
檔案　編輯　查看　插入　格式　資料　工具　擴充功能　說明　圖譜工具
檢查資料（不推送）　← 只檢查，網站不會變
推送 graph.json 到網站　← 檢查並更新網站
沒看到「圖譜工具」？

按鍵盤 F5 重新整理頁面，再等幾秒。第一次使用時，Google 會跳出「需要授權」：選自己的帳號 → 若出現「Google 尚未驗證這個應用程式」，點「進階」→「前往（不安全）」→「允許」。這是本專案自己的程式，可以放心允許。

5認識分頁

程式是看分頁名稱的開頭決定這一頁是什麼資料。英文大小寫都可以，但開頭一定要對。

分頁內容
nodes_ALL所有節點
link_ALL所有連線
nodes_color節點分類與顏色
links_color連線分類與顏色
missing_node程式自動產生：連線用到、但還沒建立節點的名稱。不用手動編輯。
檢查報告程式自動產生：每個橘色格子的原因。不用手動編輯。
其他名稱程式不讀，例如「supbase後台資料」「文獻資料庫」。
也可以照以前的習慣，每人或每個主題開自己的分頁

名稱開頭是 nodes_、node_ 或 link_ 的分頁都會被讀到，例如 nodes_竺庭、link_竺庭。不想讓某個分頁上網站，就在名稱前面加底線，例如 _nodes_草稿。

欄的順序不能換

程式是看「第幾欄」讀資料，不看標題文字。請不要在中間插入新欄、也不要調換欄的順序。想加自己的備註，請放在 J 欄以後，程式不讀。

id 的三個規則

  1. 一旦用了就不要改。連線是用 id 找節點，改了 id，連線那邊也要一起改。
  2. 一字不差。全形半形括號、空格、同音異字，程式都會當成兩個不同的節點。例如「尤幹 (Yukan)」和「尤幹（Yukan）」是兩個節點。
  3. 同一個節點可以出現在不同的節點分頁，但分類（B 欄）要一樣。說明（C 欄）會自動合併；分類和年份以最前面那一頁的為準。

程式會幫你處理的小事
  • 關係分類裡多打的空白會自動忽略：「活動/行動 參與」等於「活動/行動參與」。
  • 同一條連線重複填了，網站上只會出現一次。
  • 連線用到、但還沒建立的節點，網站上仍會出現，但會是「自動增加」節點，沒有分類和說明。請盡量補進 nodes_ALL。

8分類與顏色（nodes_color、links_color）

這兩頁列出所有可用的分類：A 欄是分類名稱，B 欄是色碼（例如 #E63946）。

  • 要用新的分類，先到 nodes_color（或 links_color）加一列並填色碼，再回節點或連線頁使用。沒有登記的分類，檢查時會標橘色提醒。
  • 網站上的顏色與形狀：網站會把節點分類歸成 8 大類來上色和排位置：人物、組織、地景與聚落、事件、物質文化、文獻、計畫與行動、其他。例如「政府機關」「大學」都歸「組織」，「空間」歸「地景與聚落」。
  • 全新的分類名稱（目前清單沒有的）請告訴工程師加上對應，否則網站會把它歸到「其他」。

9檢查資料：看懂顏色標記

按 圖譜工具 → 檢查資料（不推送），程式會掃過所有分頁、在有問題的格子塗色，並跳出一個摘要視窗。這個按鈕不會改動網站，可以放心多按幾次。

10推送到網站

  1. 確認「檢查資料」沒有淺紅、淺黃（或你確定可以先上線）。
  2. 按 圖譜工具 → 推送 graph.json 到網站。
  3. 右下角出現「同步中，請稍候…」，約 10～30 秒後跳出結果視窗。
  4. 看到「推送成功」後，照第 11 節等待與確認。
視窗訊息意思怎麼做
同步完成
推送成功（HTTP 200 或 201）		已送到網站資料庫。等 5 分鐘再看網站。
同步完成
資料無變動，跳過推送		內容和網站上的一模一樣。正常，不用處理。
同步失敗
找不到 GITHUB_TOKEN		試算表的金鑰沒有設定。聯絡管理者。
同步失敗
GitHub 回應 HTTP 401 / 403 / 404		金鑰失效或權限不足。截圖給管理者。
同步失敗
GitHub 回應 HTTP 409		剛好有別人同時在推送。等一分鐘，再按一次推送。
其他訊息—截圖給管理者。

11等待與確認

推送成功後，GitHub 會自動重新產生網站，大約要 3～5 分鐘。這段時間網站還是舊的，屬於正常現象。

  1. 等 5 分鐘。
  2. 打開網站，按 Ctrl + Shift + R（Mac 是 ⌘ + Shift + R）強制重新整理。
  3. 找到剛改的節點，確認名稱、說明、連線都正確。
  4. 還是舊的：不要一直重複按推送。等了 15 分鐘還是舊的，開第 3 節的「網站產生紀錄」：最上面一筆如果是紅色叉叉，截圖給管理者。
改資料不用找工程師

只要是節點、連線、分類的修改，按推送、等 5 分鐘就好。只有要改網站的外觀或功能，或要新增全新的分類對應，才需要工程師。

12填寫規則

  • 同一個人、地點、組織只能有一種寫法。全形半形括號、空格、同音異字，都會變成兩個不同的節點。
  • 名稱一旦用了就不要隨便改；改了的話，連線那邊也要一起改。
  • 新的分類要在 nodes_color 或 links_color 加一列並填色碼；全新的分類名稱請告訴工程師加上對應。
  • 年份只填數字，例如 1957。不知道就留空；結束年份可以填「現在」或「至今」。
  • 經緯度：F 欄填經度（121 開頭），G 欄填緯度（24 開頭）。
  • 試算表的欄位順序不能換；自己的註記寫在 J 欄以後。
  • 同一條連線重複填了，網站上只會出現一次。
